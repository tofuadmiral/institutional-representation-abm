# Public message-board cohort: prospective implementation and verification

November 4, 2026. This is prospective software development after the completed
controlled office-sacrifice diagnostic. It contains no new LLM observations,
prepared scientific root, allocation or paid launch. The published controlled
result and failed earlier replication remain unchanged.

`paper3/message_board_runtime_v1.py` supplies a durable adapter around the
separate simulator in `paper3/message_board_handoff_v1.py`. It takes explicit
coordinator verification, ledger, admission, transport and receipt dependencies.
The adapter itself has no credential reader or default provider sender. The separate
coordinator in `experiments/paper3_message_board_handoff_v1.py` implements proposal,
preparation, run and offline audit modes. Preparation requires separate externally
pinned human scope and genuine current-source readiness; neither preparation nor
the offline proposal allocates money or makes model calls.

Each episode reconstructs its agents' separate public-output histories and the
prior-round board before constructing the next request. The shuffled episode and
control order is deterministic. A missing post remains missing in the next round;
there is no summarizer, repaired text, inferred decision or hidden-reasoning reuse.
Only the chair executes the simulator's final selection. A review is unresolved.
The private-work arm holds focal calls constant, not total system computation.

The new action decoder is specific to this task's `post_message`, `select_plan`
and `report_fact` schemas. It requires the requested tool, exact typed fields and
the public-message UTF-8 byte bound. Complete plain-text JSON is a local content
failure under this tool-only task, not a reason to regenerate. Partial, dual,
wrong-tool or unknown action channels remain instrument failures. The request
is reconstructed from the saved public history, including the same request seed.

Native reasoning, usage, route, receipt accounting, output-limit checks and
durable response recovery use the existing frozen functions. The stream grammar
is bound to the prospective tool name without mutating old module globals.
Unknown complete channels are checked before the output-limit predicate so that
a length ending cannot hide them. New action decoding does not reclassify any
historical response.

The original durable service preserves each physical reservation and raw record,
replays complete saved responses after an index crash, and settles a saved answer
after an interrupted RESERVED settlement without another POST. Uncertain sent
requests stop for review. Latest paused terminals cannot be repeatedly invoked.
Known eligible failures use identical wires/seeds, the existing 300/600/1200
cooldowns and receipt slots. Exhausting one action's four physical attempts records
missingness and continues the remaining fixed assignments. Unknown failures,
global caps and the finite window are not silently waived.

The auditor rebuilds every dynamic request, board event, control and outcome;
checks all raw/attempt/accepted/missing/transition inventories, retry timing,
admission freshness, physical charges and full-ledger hashes; and requires equality
of the entire report. `paper3/message_board_budget_v1.py` adds a prospective
namespace over the complete unchanged authority graph, including the completed
office-probe ledger. Importing either module allocates nothing.
